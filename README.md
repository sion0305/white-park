# 화이트 파크 실시간 서버

화이트 파크 3D 스키장을 여러 사람이 함께 타게 해 주는 작은 Node.js 서버예요. 서버 하나가 두 가지 일을 해요.

1. `public/index.html`(스키장 페이지)을 웹으로 보여줘요.
2. `/ws` 주소로 실시간 연결을 받아서, 같은 채널에 있는 사람들끼리 서로의 위치, 줄 선 순서, 눈덩이·눈사람·천사 자국을 주고받게 해요. 모두의 시계도 서버 시각에 맞춰서 리프트 의자와 곤돌라가 모든 화면에서 같은 자리에 와요.

그래서 같이 줄을 서고, 앞에서부터 세 명씩 같은 의자나 곤돌라에 타는 것까지 화면마다 똑같이 보여요.

## 폴더 구성

```
white-park-server/
├─ server.js          실시간 서버 (페이지 제공 + WebSocket)
├─ package.json       필요한 패키지는 ws 하나
└─ public/
   └─ index.html      스키장 페이지 (서버 주소에 자동으로 연결)
```

## 내 컴퓨터에서 실행해 보기

Node.js 18 이상이 필요해요.

```bash
cd white-park-server
npm install
npm start
```

브라우저에서 `http://localhost:8080`을 열어요. 함께 타는 걸 확인하려면 일반 창 하나와 시크릿 창 하나로 각각 들어가세요. 같은 브라우저의 일반 창 두 개는 저장된 이름과 시즌권을 같이 쓰기 때문에 같은 사람처럼 보여요.

## 배포하기

WebSocket 연결을 계속 유지할 수 있는 곳이어야 해요. Vercel·Netlify의 서버리스 함수처럼 요청마다 잠깐 실행되는 곳은 맞지 않아요.

**Render (가장 간단)**
1. 이 폴더를 GitHub 저장소에 올려요.
2. Render에서 New → Web Service로 저장소를 연결해요.
3. Build Command는 `npm install`, Start Command는 `npm start`로 설정해요.
4. 배포가 끝나면 나오는 `https://...onrender.com` 주소가 바로 스키장 주소예요. HTTPS와 WebSocket(wss)이 자동으로 붙어요.

**Fly.io, Railway**
같은 방식으로 Node 앱으로 올리면 돼요. 포트는 플랫폼이 넣어 주는 `PORT` 환경변수를 그대로 써요.

**직접 운영하는 서버(VM)**
`pm2 start server.js`처럼 프로세스 관리자로 띄우고, 앞단의 nginx에서 HTTPS를 처리하면서 `/ws` 경로는 WebSocket 업그레이드 헤더를 넘겨주게 설정해요.

```nginx
location /ws {
  proxy_pass http://127.0.0.1:8080;
  proxy_http_version 1.1;
  proxy_set_header Upgrade $http_upgrade;
  proxy_set_header Connection "upgrade";
}
location / { proxy_pass http://127.0.0.1:8080; }
```

## 환경변수

| 이름 | 기본값 | 설명 |
|---|---|---|
| `PORT` | 8080 | 서버 포트 |
| `ROOM_CAP` | 40 | 채널 하나에 들어갈 수 있는 최대 인원 |
| `ALLOWED_ORIGINS` | (비어 있음) | 쉼표로 구분한 허용 주소. 예: `https://whitepark.example.com`. 비워 두면 어디서든 접속을 받아요. |

상태 확인용 주소 `/health`는 `ok`를 돌려줘요. 배포 플랫폼의 헬스 체크에 쓰면 돼요.

## 페이지를 다른 곳에 따로 올릴 때

`index.html`을 CDN이나 정적 호스팅(S3, Cloudflare Pages 등)에 따로 올리고 서버는 실시간 연결만 맡길 수도 있어요. 그때는 `index.html` 위쪽의 이 줄에 서버 주소를 적어 주세요.

```html
<meta name="white-park-server" content="wss://실시간서버주소/ws">
```

서버가 페이지를 직접 보여줄 때는 비워 두면 같은 주소로 알아서 연결해요. 파일을 컴퓨터에서 그냥 열면 혼자 노는 모드로 동작해요.

## 채널

한 채널에 `ROOM_CAP`명까지 들어가요. 새로 들어온 사람은 자리가 남은 채널 중 가장 붐비는 곳으로 들어가서 사람들끼리 자연스럽게 만나요. 친구끼리 같은 채널에서 만나려면 주소 뒤에 번호를 붙여요.

```
https://스키장주소/?ch=7
```

## 알아 둘 점

- **눈덩이·눈사람·천사 자국:** 서버 메모리에만 저장돼서, 서버를 다시 시작하면 사라져요. 원래도 1시간(천사 자국은 5분) 뒤에 사라지는 것들이에요.
- **시즌권과 이용 시간:** 각자 브라우저에 저장돼요. 기기를 바꿔도 이어지게 하려면 계정이나 익명 ID와 데이터베이스를 붙여야 해요.
- **악용 방지:** 접속자 인증은 없어요. 메시지 크기 제한과 초당 메시지 수 제한만 들어 있어요. 공개 서비스로 운영하려면 닉네임 욕설 필터와 신고 기능을 더하는 게 좋아요.
- **규모:** 움직이는 사람 한 명이 초당 10번 위치를 보내기 때문에, 한 채널에 40명이 모두 움직이면 접속자 한 명이 받는 양이 초당 100KB 안팎까지 늘어요. 휴대폰 사용자가 많다면 `ROOM_CAP`을 20~30으로 낮추는 걸 권해요. 동시 접속이 수천 명을 넘으면 서버를 여러 대로 나누고 채널별로 서버를 정해 주는 구성이 필요해요.
